# Pin Node 24.21.0 across toolchain+produzione (PSG-13)

> **Linear:** PSG-13 — "Tighten engines.node and pin Node explicitly for Railway" (parent PSG-9,
> the Nest 12 lockstep move). Backend/tooling only. To land **before** the lockstep move so the
> build env is already valid when Nest 12 arrives.
>
> Small, precise tooling change — the flowchart's "judgment call" tier: two one-line pins, no
> runtime code. No separate design spec beyond the reasoning in this plan.

## Decision (user-approved 2026-09-19)

One Node version, pinned in the **two places that actually control the build/runtime**:

| Source | Change | Why |
| -- | -- | -- |
| `package.json` → `engines.node` | `"24.21.0"` (was `"24.21.0"`-shaped? **was `">=22.12.0"`**) | single exact pin; satisfies Nest 12 schematics `^24.15.0` and current Nest 11 toolchain |
| `.github/workflows/ci.yml` | `node-version: 24` → `24.21.0` | CI no longer floats on 24.x |

**Deliberately NOT touched** (user directive):
- **No Railway env var** (e.g. `NIXPACKS_NODE_VERSION` / `RAILPACK_NODE_VERSION`) — Railway's
  build reads `engines.node` from `package.json` directly, adding an env var would be a redundant
  fourth source of truth that drifts. Pinning `package.json` **is** the Railway pin.
- **No `.nvmrc`** — local runtime is managed by **mise** (24.21.0), no nvmrc in this repo.
- **No Dockerfile** — not needed; Nixpacks is deprecated and not used here.
- **No `engineStrict`** — not required for the pin to take effect.

Target: `24.21.0` everywhere.

## Why `24.21.0`

- Matches local **mise** (`24.21.0`) → local === CI === production.
- Matches the **binding constraint**: `@nestjs/schematics@12` requires `^22.22.3 || ^24.15.0 || >=26.0.0` → `24.21.0` ≥ `24.15.0` ✓ (the Nest 12 move consumes this).
- Satisfies the current range `>=22.12.0` ✓ and current Nest 11 toolchain ✓.
- Single exact pin kills the `22.12–22.22.2` window where `nest build` has no toolchain.

## Files (3 touched, 2 left alone)

1. `package.json` — set `engines.node: "24.21.0"`
2. `.github/workflows/ci.yml` — `node-version: 24` → `24.21.0`
